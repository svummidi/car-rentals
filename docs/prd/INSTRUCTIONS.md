# PRD Maintenance Instructions

- Treat `prd-accounting.md` and the originating issue’s embedded requirements as the current accounting PRD scope. No separate source requirements file was present when this document was prepared.
- Preserve the 12 functional requirement IDs and their source-module traceability when revising requirements.
- Do not infer accounting treatments, tax rates, approval thresholds, timelines, or other policy. Add unresolved decisions to the open-questions table with their business impact.
- Keep user stories mapped to functional requirements, and retain testable Given/When/Then acceptance criteria.
- Maintain the explicitly stated MVP constraints and exclusions. Do not promote potential future enhancements into MVP requirements without approved source direction.
- Update the version history when changing the PRD and distinguish draft documentation from stakeholder approval.
- This is a business requirements document; do not add application code, APIs, UI specifications, or database schemas here.
